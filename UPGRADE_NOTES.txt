LifeCare Form Builder V5 — incremental from V4

Added: per-form spreadsheet calculated columns, restricted safe row formula parser, copy/paste rectangular ranges, undo/redo for unsaved edits, column resizing/freezing, distinct-value/text filters, 5-minute idle polling pause. XLSX exports calculated values.

PDF: max 5,000,000 bytes, image cap unchanged at 4,000,000; warning for PDFs above 4 MB, two-part authenticated upload, streamed original download; memory-only per-document/session cache for repeat previews/downloads, bounded to about 20 MB/eight entries. Local PDF.js viewer integration with page navigation, pinch/double-tap zoom, zoom buttons, fit, and fallback to native viewer.

Preserved V4 QR template, permanent form URLs, existing data store and form-level response/merge/admin rules.

Limitations: formulas are per-row numeric formulas only; XLSX exports their values, not Excel formulas. Paste cannot change record identity or derived cells; undo works before save only. Browser navigation is blocked in this environment; local dependency build and real mobile/Netlify testing are not verified. Large attachments and PDF.js still consume bandwidth on first access. No automatic production deployment was made. See README for deployment and acceptance tests.

V6 — Adult screening reference values and image viewer
- Existing optional Height + Weight and BP blocks now display live BMI, adult category, normal-BMI reference weight (18.5–22.9 kg/m²), and BP reading category. No extra request is needed. Missing or invalid pairs do not generate a result. Known age <=18 suppresses adult reference classifications; adult-only warning is displayed. These are screening references, not diagnoses or individualized weight goals; not for pregnancy or children. Clinical owner should approve before use.
- BMI reference: Malaysia MOH Clinical Practice Guidelines, Management of Obesity (2023), table 2-1. BP retains the AHA adult categories used in earlier builds, with a low-reading flag and urgent assessment message at >=180 systolic or >=120 diastolic. Sources: https://www.moh.gov.my/images/04-penerbitan/penerbitan-klinikal/panduan-amalan-klinikal/CPG_Management_of_Obesity_Second_Edition_2023.pdf ; https://www.heart.org/en/health-topics/high-blood-pressure/understanding-blood-pressure-readings/
- Live response sheet and XLSX export show the reference range and recalculate from saved/consolidated readings. Separate submissions remain separate; public forms never get additional health fields unless the owner adds the health blocks. Respondent preview uses entered readings only; it does not expose historical patient measurements.
- Image attachment preview now includes fit, zoom +/−, fullscreen, pinch and double-tap controls, with Download and Share (public attachments only) and the same temporary memory cache as PDFs. Images remain limited to 4 MB; PDFs to 5 MB. No respondent upload feature introduced.
- 14 automated tests and inline JavaScript syntax checks passed. No live Netlify or physical-device tests; verify touch gestures, rendering, and clinical labels before production.

V10 — optional laboratory screening blocks
- Added fasting capillary glucose, random capillary glucose, 2-hour OGTT glucose, and total cholesterol as independently selectable question types. Each is stored as a numeric custom-field answer (mmol/L); no default/legacy form is modified, no extra polling, no additional service.
- The respondent sees a local calculation and reference chart immediately. The shared classifier supplies text status columns in the live response grid and .xlsx export, including updated merged or edited readings. Invalid, blank and known paediatric ages do not produce adult labels. Existing V9 BMI rounding, BP categories and all other features are retained.
- Owner-supplied high screening flags are fasting >=5.6, random >=7.8, OGTT >=7.8 and total cholesterol >=5.2 mmol/L; glucose below 3.9 is flagged Low. Do not round laboratory values before classification. These are screening flags, not diagnostic criteria or treatment targets; clinical team should approve them before use, especially pregnancy and special populations. Random capillary and 2-hour OGTT are separate questions, not interchangeable tests. Input is mmol/L only to prevent unit confusion; numeric input must be positive and <=100. No mg/dL conversion is implemented.
- Source context: MOH Malaysia T2DM CPG 6th edition (2020), screening section; MOH Malaysia Dyslipidaemia CPG 6th edition (2023), section 1.3 uses TC >5.2, not >=5.2. The stricter owner threshold is therefore labeled a LifeCare screening rule. Existing BP categories use AHA, not Malaysian CPG staging. Sources: https://www.moh.gov.my/images/04-penerbitan/penerbitan-klinikal/panduan-amalan-klinikal/CPG_T2DM_6th_Edition_2020_13042021.pdf ; https://www.moh.gov.my/moh/resources/Penerbitan/CPG/CARDIOVASCULAR/e-CPG_on_Dyslipidaemia_2023_6th_Ed.pdf
- Corrected stale 4 MB image-upload helper label to match existing 5 MB limit. No change to attachment implementation.
- Local automated tests cover threshold boundaries, numerical validation, separate and merged submissions, administrator edits and the actual shared spreadsheet/export column functions. Browser, physical-device and live deployment acceptance testing still required.

V11 — proportional glucose and cholesterol indicators
- Replaced the respondent's laboratory reference table with a colour-coded linear gauge matching the existing BMI visual style. The marker uses the entered, unrounded reading; fasting glucose cut-offs 3.9/5.6, random and OGTT 3.9/7.8, total cholesterol 5.2 mmol/L. Reference legend and screening caution remain. Display axes are 0–10 for fasting glucose/cholesterol and 0–14 for random/OGTT; these endpoints are visual bounds only. Higher readings are shown at the right endpoint with an explicit overflow note. Blank/invalid values have no marker; known paediatric ages suppress the adult gauge.
- No changes to classification, response storage, XLSX export or Netlify request behavior. All 22 automated tests and inline JavaScript syntax checks passed. Headless browser check timed out; complete browser and physical-device acceptance tests remain outstanding.

V12 — Admin workflow cleanup
- Edit Form combines title, question builder and per-form Settings (response rules, schedule in Malaysia time, closed message and Thank You page). Settings are staged and applied together with Save form. Creating a form opens the editor immediately; creation still saves an empty form as in V11.
- Share Link groups copy, customize short link, and authorized response-management link. Existing aliases and permanent QR destinations are retained.
- Distinct Open / Closed / Closed (scheduled or expired) indicators use local time comparisons without extra requests. Manual switch does not override dates. Local status updates every 15 seconds without polling the backend.
- Admin management and Add admin are at the top right for master users only.
- Form configuration and alias edits set a backend updated timestamp. Default sort is recently edited; existing forms without this timestamp fall back to creation date. Response submissions and response edits do not change form ordering. Namelist updates do not count as form configuration edits.
- One per-form Export Excel menu supports all or currently filtered records; global export remains separate.
- Response polling pauses while editing forms or viewing the new dialogs. No respondent interface changes.
- 23 simulated tests passed, inline JavaScript syntax checked. No deployed site or physical device verification performed.

V13 — QR customization inside existing admin modal
- Click a form's QR code button to open a responsive customization panel with the full V4-style LifeCare poster as the preview and default export. The poster title comes from the selected saved form. The QR always encodes the immutable form ID, not its editable alias.
- Choose square, rounded, or dotted patterns and a sufficiently dark colour. The header and centre logos are independent: no logo, supplied LifeCare logo, or custom PNG/JPEG/WebP (2 MiB maximum, resized locally to 512 pixels maximum edge). Choices and custom logos are temporary for each QR session; nothing is uploaded to Netlify. Default: LifeCare header, square black QR, no centre logo.
- Function patterns and four-module white quiet zone are preserved. Centre logo sizes are capped and must avoid reserved modules; branded/stylized QR uses high error correction. The browser checks the rendered QR's exact destination (BarcodeDetector or existing locally built ZXing bundle) before enabling PNG, SVG or print. If verification fails or the decoder is unavailable, exports remain disabled. Physical phone scanning is still recommended before mass printing.
- All exports retain the full poster, with the border, form title and scan instruction; 3200px PNG width, SVG and A4/A5/A6 print-to-PDF. No printed URL or expiry date. No backend changes, polling or paid services introduced.
- Tests: 25/25 Node tests passed; six generated SVG poster variants were independently rasterized and decoded with OpenCV, all matched distinct test URLs. Admin inline JavaScript and QR scripts passed syntax checks. Browser runtime decoder, actual print output, mobile scanners and live Netlify deployment remain unverified. Run npm install and npm run build as in V12 to bundle ZXing/PDF.js before deployment.
