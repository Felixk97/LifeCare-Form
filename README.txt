LifeCare Multipurpose Form Builder — v5 spreadsheet and PDF upgrade
==========================================================
This source package extends the previously supplied Netlify project. It is not a static-only website. The /api and /f/:slug Netlify Function requires a normal Netlify build with npm dependencies and Netlify Blobs.

DEPLOYMENT
1. Back up your current GitHub project and export existing form responses before changing production. Keep a copy of the original ZIP.
2. Extract this ZIP. Replace the project files at the ROOT of your existing GitHub repository (not inside a second nested directory). Keep netlify.toml, package.json, scripts/, netlify/functions/, public/ and the other root files together.
3. Keep your existing Netlify site connected to the repository, with the existing ADMIN_CODE environment variable scoped to Functions. Choose a strong, unique master password (preferably at least 20 random characters). Do not put it in the source code.
4. The build command is npm run build, publish directory public, functions directory netlify/functions, Node 22. Dependencies are installed by Netlify; the build copies ZXing and PDF.js assets into public/vendor. No extra paid service or database subscription is required by this design.
5. Deploy a test site first using synthetic data only. Check QR scanning, logins, merges, Excel downloads and PDFs. Real Netlify billing limits still apply. Do not use real confidential records until live acceptance/security checks pass.
6. Open /admin.html. Master: username blank or master; enter your existing ADMIN_CODE. New sub-admins use their unique username and password. Existing legacy access-code users can leave username blank until migrated.

USAGE
* Create form: new forms start blank, public, separate responses, no respondent editing, name optional. Edit Fields to add questions or content. Name, barcode, screening questions, merging and staff access are not compulsory. Existing form IDs and configurations are retained; existing records remain in the original screening blob store.
* Settings: independently choose public/staff, separate/merge, matching barcode or a unique text/number/email question, private edit link or no editing, optional name, sensitivity marker, and 30/60-second or manual refresh. To merge, assigned staff must sign in. Unanswered fields keep their earlier values; new nonempty values replace older ones, including zero. Merge submissions may be partial even if questions were marked required; the matching key must be present. Use distinct IDs per screening event/form. Existing duplicate matching records must be reviewed before enabling merge. Use Duplicate review in the response sheet to export an XLSX report grouped by matching identifier. No automatic name-based combining of old records.
* Schedule & Thank You: set Malaysia-time opening and closing dates, change closed-form message, confirmation heading/message, optional external action button and Submit Another Response visibility. Changes apply to future page loads; opening/closing is enforced on submission.
* Fields: add headings, subtitles, visual or paginated sections, questions, optional camera barcode field, PDF/image/link content. PDFs are uploaded by the owner only, up to 5 MB (5,000,000 bytes); images also support 5 MB. A warning is shown above 4 MB for either type. Larger attachments are uploaded in two parts; the original file is served using a streamed response. Save the form to publish the attachment. Preview opens the original document/image in a dialog; public documents support Share and Download. Restricted documents permit authorized download but direct public sharing is disabled. Browser support determines native file sharing and inline PDF display. If unavailable, open the document in the browser PDF viewer or download.
* QR code: real local QR generation, using the existing LifeCare logo, actual form title, no printed URL or deadline, and Scan to Complete This Form. Download high-resolution PNG or vector SVG, or use Print / Save PDF (A4/A5/A6). The design preview under design/ is illustrative and uses a non-live URL. The QR encodes the immutable canonical form URL. Short links are copied separately; new forms receive an automatic short link and admins can claim a custom alias. Old aliases remain reserved and cannot point to another form after deletion.
* Responses: click a form title to open the grid. Search any visible column, sort headers, edit cells (authorized users only), Save/Cancel, inspect history, export all/filtered XLSX. Existing data not overwritten by stale edits; the API rejects conflicts and the user must refresh/retry. The grid pauses polling during edits and when hidden/closed. Auto-refresh defaults to 60 seconds, optional 30 seconds/manual; unchanged data checks avoid downloading all records. Excel files are snapshots, not live database connections. Excel/QR libraries run locally without a CDN.
* Administrators: create per-user username and password, assign allowed forms, set view/export, edit, staff-submit, delete and configuration permissions. Login sessions expire after 8 hours and password resets invalidate existing sub-admin sessions. The response management link requires login; it is separate from the public respondent link. View and export are one permission because anyone who can read response data can copy it.

DATA MIGRATION AND LIMITATIONS
- Old ID-only respondent edit links no longer work. New private edit links carry a random token in the URL fragment, and only its hash is stored; new forms default to no respondent editing.
- Older forms and their stored records are kept, but the previous display-only name-matching heuristic is removed to avoid combining distinct people. If duplicate legacy barcodes exist, export/review manually before enabling actual merge.
- Legacy sub-admin codes remain accepted for compatibility; assign a username and a new password to migrate them. New passwords are stored with salted scrypt verifiers. The sensitivity checkbox is a classification marker; all response records are protected, regardless of the marker. Full enterprise audit, retention automation, malware scanning, advanced rate limiting and independent security review are not included. Staff-access forms are the restricted-access option; separate invitation accounts are not included.
- Netlify Blobs uses conditional ETag updates to protect individual records. Merge submissions retry a conflict up to four conditional write attempts against fresh data; overlapping values use the latest successful write. Admin cell edits still reject stale revisions; it is not a transactional database. Configuration changes and concurrent submissions during a mode switch should be tested and managed carefully. Close a live form before changing merge mode/key. Form owner media replacements create new stored objects; old unreferenced uploads are not automatically garbage collected. Deleting a form deletes its stored response and media keys; short aliases remain reserved.
- Camera and native share must be verified on physical Android/iPhone devices. Section display is configurable in Settings: single scrolling page (default, preserves existing layouts) or separate pages with Back/Next and progress. Required field validation still runs on final submission. QR supports PNG, SVG and browser print-to-PDF. The grid supports a restricted per-row numeric formula engine, not the full Excel formula language.
- No live deployment was performed. Real npm build, device/browser interactions and production Netlify storage behavior need testing. PDFs above 4 MB are uploaded using two requests and returned using a streamed response; verify on your actual plan. The environment blocked dependency installation and headless browser navigation. V5 includes mocked API, formula, clipboard and cache tests. Two V4 QR posters were independently decoded and mapped to distinct sample URLs. V3 Excel generation was retained. Browser navigation in this environment remains blocked; real browser print, multi-page UI and native camera/share interactions remain unverified.

V5 SPREADSHEET AND PDF FEATURES
* Click a cell, then Shift-click another for a range; Copy range or Ctrl/Cmd+C. In Edit mode, select the top-left cell and paste a TSV range using Paste range or Ctrl/Cmd+V. Read-only columns and merge identifiers are protected; paste rejects a range with changes to those cells. Pasting operates on visible filtered/sorted rows. Undo and Redo apply to unsaved changes only (up to 100 checkpoints). Saving still uses server revision checks per row; a multi-row save is not an atomic transaction.
* Drag the header's right edge to resize; Freeze can pin up to three left columns. Width and freeze preferences are local to this browser and form. Header filter buttons support text matching and distinct-value selection; columns with more than 1,000 values use text matching. Search, filters and sorting use saved response values while editing.
* Calculated columns: an admin with form configuration permission can add up to 15 formulas per form, using stable field references shown in the editor (e.g. =ROUND([weight]/([height]/100)^2,2) or =[x:amount]*[x:qty]). Supported operators: + - * / ^ and parentheses; functions SUM, AVERAGE, MIN, MAX, ABS, ROUND. Formulas operate on the current row only, not spreadsheet ranges, other sheets or other calculated columns. Missing numeric inputs show blank; invalid calculations show #ERROR. Calculated values update while editing and are included in XLSX exports as values, not native Excel formulas. Definitions are stored per form, not in responses.
* PDF preview loads on demand and caches original bytes in memory by document URL and session (up to approximately 20 MB, eight entries; evicts older entries). Closing and reopening a preview or downloading again reuses the cached bytes without a new API request while cached. Reloading or navigating away clears the cache. Native share can send the cached file if supported; opening a shared URL on another device transfers it again. Restricted documents remain unavailable for public sharing.
* PDF.js is loaded on demand from the local build, with page navigation, pinch zoom, zoom buttons, double tap and fit/full-view controls; if it cannot render, use native PDF preview or download. Test on actual iOS and Android devices. PDF.js adds initial static asset downloads; the original PDF is not fetched again to render pages.
* The response viewer pauses after five minutes without interaction, as well as when hidden or editing. Automatic refresh resumes on activity; 60 seconds remains default, 30 seconds and manual are optional.
* Abandoned partial PDF uploads may remain in storage until the form is deleted; a failed upload attempts cleanup, and expired upload sessions are rejected.
* Browser navigation and package installation are not verified here. npm install / npm run build, real Netlify response streaming, browser gestures, clipboard permissions and production behavior remain acceptance-test items.
