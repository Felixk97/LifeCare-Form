LIFECARE FORM BUILDER V18 — consolidated Platform-chat upgrade

BASE: LifeCare_Form_Builder_v17.zip, recovered from the file library. Deploy to the SAME Netlify site; retain ADMIN_CODE and existing environment variables. No new paid service or migration is required. Do not delete the existing Netlify Blobs stores. Export important existing records before deployment and use a test/preview environment first. This package contains code, not a copy of production records. Existing form IDs, question IDs, aliases, blob keys, attachments, accounts and records are not rewritten by this release.

WHAT CHANGED
• QR: approved V16/V17 fixed full poster retained (original logo proportions, Calibri Bold form title, no divider above title, two bottom illustrations). Square, rounded, dotted and artistic/image-textured modules. Logo remains exactly centred. Choose none, LifeCare or upload a logo. Adjustable logo size in odd module increments; generator chooses a QR version with a safe centre and may reduce the logo when needed. No silent off-centre move or logo removal. Artistic mode uses a dark, contrast-preserving texture clipped to non-functional dark data modules, NOT a full photographic or arbitrary AI QR. Functional marks and white quiet zone retained. Download/print only after local decoder confirms exact permanent form URL. PNG 3200px wide, SVG, print-to-PDF retained. Customization choices are temporary until the panel closes. Sample preview uses example.com, not a deployed form.
• Form editor: responsive full-screen mobile layout, sticky Settings/Save/Cancel, explicit description directly after title, dedicated PDF/image/link header attachment controls, separate Add Section button, section insertion picker and question types. Content blocks do not create Excel columns. Header attachments are always shown before the questions, including on paged sections. Existing 5 MB media limit, preview/download/share/cache are retained. Individual question IDs are preserved when moving items.
• Date fields: native calendar control, explicit calendar button on browsers with showPicker(), native fallback; ISO dates validated on the server (including invalid calendar days). No new date dependency.
• Linked required: same letter (A–Z) on two or more questions. Answering any visible group member (including numeric zero) makes all visible members required. Hidden/skipped questions are not required. Both client and API check. Existing unlinked progressive merges still accept partial readings. Legacy merge forms with linked groups keep previous behavior until saved in V18, when explicit groups are enabled. Admin corrections retain their authorized workflow. Built-in age, height/weight and BP can be linked; barcode remains independent because it is a matching identifier.
• Branching: select the destination for a choice, dropdown, Yes/No or multiple-choice answer. Jump forward to a later question/section or end of form. If several checked options have branches, the first configured option in list order wins; an existing unconditional multi-choice branch is retained as default. Text/number/date/measurement questions support an unconditional forward destination, not arbitrary expression-based conditions. Hidden answers are excluded from submissions. Existing inline/paged display remains configurable; required validation occurs on final submission and returns the user to the relevant section. Header attachments are not branch targets.
• Button tooltips: hover and keyboard focus, touch-hold hint on mobile; major controls and dynamic form-list actions included. No polling or new backend requests for QR, tooltips, calculations or date UI. Existing response refresh behavior retained.
